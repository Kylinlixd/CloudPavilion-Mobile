# CloudPavilion 自助注册设计

## 目标

让没有账号的新用户先创建普通账号，再登录并创建或加入家庭。未登录用户始终不能访问或调用创建家庭功能。

## 用户流程

1. 登录页提供“创建账号”入口。
2. 注册页收集用户名、密码和确认密码；家庭 ID 不属于注册信息。
3. 注册成功后，后端返回用户摘要和一对 JWT，移动端安全保存 token，并把用户视为已登录。
4. 没有家庭 ID 时进入现有的无家庭状态，用户从设置页创建家庭；创建成功后保存返回的家庭 ID。
5. 已有账号的用户仍通过原登录流程进入，行为不变。

## 后端接口与安全

- 新增 `POST /api/v1/auth/register/`，允许匿名访问。
- 请求字段：`username`、`password`、`password_confirm`。
- 响应状态为 `201`，字段为 `user`、`access`、`refresh`。
- 使用 Django 用户名校验、唯一约束和 `validate_password` 执行现有四项密码策略；密码只通过 `set_password` 保存。
- 密码与确认密码不一致、用户名重复或密码过弱时返回字段级 `400` 错误。
- 注册接口采用 `ScopedRateThrottle`，限制为每个匿名来源每分钟 5 次；创建家庭接口继续使用 `IsAuthenticated`。
- 用户创建与 token 生成放在同一服务调用中；不会自动创建家庭或授予 staff/superuser 权限。

## 移动端结构

- 新增 `RegisterScreen`，复用登录页的视觉语言和输入样式。
- `AuthContext` 新增 `register(username, password, passwordConfirm)`，调用注册接口并复用现有安全存储写入会话。
- 未认证导航栈同时注册 `Login` 与 `Register`；登录页入口导航到注册页，注册页可返回登录。
- 注册按钮在提交期间禁用；后端字段错误转换为可读中文提示，网络错误保留通用失败提示。
- 注册成功后由认证状态切换自动进入主界面；用户随后通过当前“打开设置”路径创建家庭。

## 验证

- 后端测试覆盖：注册成功、重复用户名、密码不一致、弱密码、匿名创建家庭返回 401、注册用户可创建家庭且成为 owner。
- 移动端测试覆盖注册 API 的路径、请求体与 token 保存，并保留现有登录测试。
- 运行 Django 全量测试、迁移检查、OpenAPI 校验、TypeScript、ESLint、Vitest、Expo Doctor、Xcode Release 真机签名构建。
- 部署后验证匿名注册、登录、创建家庭三段链路，并重新安装到已连接的 iPhone 15 Pro Max。

## 非目标

本次不加入邮箱验证码、短信验证、找回密码、社交登录或自动创建家庭；这些需要额外的身份验证与消息服务设计。
