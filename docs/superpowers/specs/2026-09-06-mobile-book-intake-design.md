# 手机端扫码与手动添加书籍设计

## 目标

用户无需 Web 端即可在 iPhone 上向当前家庭书房添加实体书。应用同时支持扫描 ISBN 条码和手动填写；扫描命中公开书目数据时自动补全资料，未命中时无缝转入手动填写。

## 已确认规则

- 添加入口只放在移动端藏书流程中，不要求用户前往 Web 端。
- 扫码后自动补全书名、作者、出版社、出版日期、简介和封面。
- 同一 ISBN 使用共享书目元数据；同一家庭重复扫描时继续新增一个实体副本。
- 没有 ISBN 的书也允许手动添加。
- `owner`、`admin` 和 `member` 可以添加，`viewer` 不可以添加。

## 用户体验

### 藏书页

藏书页增加“添加书籍”按钮，并把空状态提示改为“扫描 ISBN 或手动录入第一本书”。点击后进入独立的添加页面。

### 添加页面

页面包含“扫码添加”和“手动添加”两个模式：

1. 扫码模式请求摄像头权限，只识别 ISBN 常见的 EAN-13 条码，并拒绝不是 `978` 或 `979` 开头的值。
2. 成功识别后暂停扫描，调用后端书目查询接口，并显示加载状态。
3. 查询命中时把返回资料写入可编辑表单，用户确认后保存。
4. 查询未命中、网络异常或第三方服务不可用时保留 ISBN，显示清楚的提示并切换到手动表单。
5. 用户可以重新扫描，避免一次误识别后卡住。

手动表单字段：书名（必填）、作者、ISBN、出版社、出版日期、分类、简介、副本条码和副本备注。封面使用查询结果 URL；本期不做手机相册上传或拍摄封面。

保存成功后进入新书详情页。重复点击保存时按钮禁用，避免生成多个副本。

## 后端接口

### ISBN 查询

新增：

```http
GET /api/v1/books/lookup/?isbn=<isbn>
Authorization: Bearer <access>
X-Family-ID: <family-id>
```

后端规范化并校验 ISBN，先查询本地 `Book`；本地未命中时查询 Google Books，仍未命中再查询 Open Library。结果转换为 `title`、`author`、`isbn`、`publisher`、`publish_date`、`category`、`description`、`cover_url` 和 `source` 字段，不把第三方响应直接暴露给手机端。只有完整的 `YYYY-MM-DD` 才写入 `publish_date`，仅有年份或年月时返回空值。成功返回 `200`，合法但未命中返回 `404`，格式无效返回 `400`。

每个外部提供方的连接与读取总超时为 3 秒。成功结果缓存 24 小时，“未命中”结果缓存 10 分钟；第三方超时或异常返回 `503`，但移动端仍可继续手动填写。

### 原子添加

新增：

```http
POST /api/v1/book-copies/add-book/
Authorization: Bearer <access>
X-Family-ID: <family-id>
```

请求包含书目字段和可选副本字段。服务端在同一数据库事务内：

1. 校验当前家庭和写入角色；
2. 按规范化 ISBN 查找或创建 `Book`，无 ISBN 时创建新书目；
3. 为当前家庭创建新的 `BookCopy`；
4. 返回书目和新副本。

相同 ISBN 已存在时保留数据库中的共享书目元数据，不用客户端字段覆盖它，只为当前家庭新增副本。并发提交时需要捕获唯一约束竞争并复用已存在书目。事务失败时不得留下孤立书目。

## 元数据提供方

- 主数据源：Google Books `volumes?q=isbn:<isbn>`。
- 回退数据源：Open Library ISBN/Books API。
- 外部 HTTP 请求只由后端发起；可选的 `GOOGLE_BOOKS_API_KEY` 只保存在生产环境变量中。移动端不保存第三方 API 密钥，也不依赖第三方响应格式。
- `Book` 新增 `cover_url` 保存转换为 HTTPS 的第三方封面地址，原有 `cover` 上传字段保持兼容。移动端优先显示 `cover_url`，没有时使用原上传封面或占位封面。

## 权限与安全

- 查询接口要求已登录且属于所选家庭。
- 添加接口沿用家庭写入角色：`owner`、`admin`、`member`；`viewer` 返回 `403`。
- 后端不接受客户端提交 `family`、`created_by` 或副本状态，这些字段由服务端绑定。
- ISBN、字符串长度、日期格式和封面 URL 均由序列化器验证。
- 查询错误不返回第三方原始异常或敏感配置。

## 移动端结构

- 使用 Expo Camera 提供条码识别与权限状态。
- 新增 `AddBookScreen`，由根导航栈承载。
- 新增小型书目 API 模块，负责 lookup 和 add-book 请求及错误归一化。
- `CatalogScreen` 在添加页返回时刷新列表。
- `BookDetailScreen` 继续使用现有书目/副本查询，不新增并行的数据模型。

## 内置品牌资源

- 将确认版方形 PNG Logo 复制到移动端 `assets/`，资源随安装包内置，不从后端或网络下载。
- 使用该资源生成 iOS 应用图标，并配置 Android 图标与启动画面。
- 登录页和注册页显示同一份本地 Logo，保证离线状态也能正常呈现品牌。
- 保留无透明通道的原始图，平台生成流程负责输出所需尺寸。

## 错误状态

- 未选择家庭：不允许进入保存流程，并引导前往设置。
- 摄像头权限未授权：解释用途，提供再次授权和手动添加入口。
- ISBN 无效：提示仅支持有效 ISBN 条码，并恢复扫描。
- 查无资料：保留 ISBN 并打开手动表单。
- 外部服务不可用：提示自动补全暂不可用，不阻断手动添加。
- 权限不足：明确提示当前家庭角色不可添加。
- 保存失败：保留所有已填字段，允许再次提交。

## 测试与验收

后端自动测试覆盖：

- 本地 ISBN 命中不请求外部服务；
- Google Books 命中及字段映射；
- Google 未命中后 Open Library 回退；
- ISBN 无效、未命中和外部服务失败；
- 原子创建书目与副本；
- 重复 ISBN 新增副本而不重复书目；
- 并发 ISBN 竞争；
- 家庭隔离和 `viewer` 写入拒绝。

移动端自动测试覆盖：

- ISBN/EAN-13 识别规则；
- 查询结果映射到表单；
- 未命中切换手动模式；
- 保存请求结构和后端字段错误展示；
- 防止重复提交。
- Expo 配置能够解析到存在的本地 Logo 文件。

真机验收：在 iPhone 上授权摄像头，扫描一本 ISBN-13 图书，核对自动补全内容后保存；再次扫描同一本书，确认书目不重复且实体副本数量增加；再手动添加一本无 ISBN 的书。

签名包验收同时确认桌面图标、启动画面和登录/注册页均使用内置 Logo，并检查 `.app` 中存在对应资源。

## 非目标

- Web 端书籍录入页面。
- OCR 识别书名或封面。
- 拍摄、裁剪或上传自定义封面。
- 批量连续扫描模式。
- 购买链接、价格与库存查询。
